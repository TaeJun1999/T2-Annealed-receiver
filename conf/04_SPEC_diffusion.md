# 04 — Diffusion / score model 지침 (사다리 + 품질 게이트)

> **핵심 원칙 한 줄.** 사다리의 심판은 **BLER이 아니라 사전 등록 품질 게이트**다. 게이트는 D1 testbed에서 잰다 — 거기에만 참 prior의 **정확 score**가 있어서 "제대로 학습됐는가"를 절대적으로 잴 수 있기 때문이다.

---

## 0. 이 문서가 해결하는 문제

"학습이 제대로 안 돼서 진 것 아닌가"라는 반론은, 사후에 제기할 수 있으면 영원히 끝나지 않는다. 끝내는 방법은 하나뿐이다: **"제대로 학습됨"을 BLER을 한 번도 보기 전에 숫자로 정의하고 얼려 둔다.**

- 게이트를 **통과한** 모델의 BLER 결과는 **그대로 받아들인다.** 나빠도 받아들인다.
- 게이트를 **통과 못 한** 모델은 arm에서 빼고 사다리의 다음 칸으로 간다. 이건 정당한 재시도다.
- **BLER이 나빠서 다른 모델로 바꾸는 것은 금지.** 이 구분이 이 문서 전체의 존재 이유다.

---

## 1. 고정되는 것 — 인터페이스

사다리는 **score model만** 바꾼다. 수신기 안으로 들어가는 방식은 고정한다:

- **one-shot Tweedie + D-13(belief) + D-14(matrix site)** — `M-ours-score`(oracle)와 **완전히 동일한 경로**.
- 다단계 annealed sampling(R-A)은 쓰지 않는다. D-17 철회로 이미 기각됐다(exp_0923 기준 미달, exp_0924는 one-shot보다 나쁨).

이렇게 고정해야 `M-ours-score`(정확 score)와 `M-ours-dscore`(학습 score)의 차이가 **score 자체의 차이 하나**가 된다. 테스트 M2와 같은 논리다.

## 2. 고정되는 것 — 학습 규약 (전 사다리 공통)

| 항목 | 값 | 이유 |
|---|---|---|
| 학습 데이터 | GMM이 받은 것과 **동일한 $N_{\rm train}=10^4$ 표본** | 데이터 예산으로 이기면 비교가 무의미 |
| train/val 분할 | 9:1, 시드 고정, 전 사다리 동일 분할 | |
| 정규화 | $\mathbb E\|\mathbf H\|_F^2=N_rN_t$ 로 통일, 실수 2채널($\mathrm{Re},\mathrm{Im}$)로 펼침 | 규약 혼선 방지 |
| $\sigma_t$ 격자 | **§3에서 측정해 정한다. 임의로 고르지 않는다** | |
| 체크포인트 | 매 epoch 저장, 재개 가능 | 긴 실행 중단 대비 |
| 시드 | 고정, 사다리 칸마다 기록 | |
| 조기 종료 | **검증 DSM loss만** 사용. BLER 미사용 | |

### 학습 예산
시간 제한은 없다. 다만 각 사다리 칸은 **검증 loss가 20 epoch 개선 없으면** 종료한다. 무한 학습하지 않는다.

**하한도 있다.** 한 칸을 "시도했다"고 말하려면 위 조기 종료 조건에 걸리거나 **최소 200 epoch**에 도달해야 한다. 그 전에 그만둔 것은 `LADDER.md`에 `ABORTED`로 적고 **칸을 소진한 것으로 세지 않는다.** 대충 돌리고 "게이트 미달"로 넘어가면 사다리 전체가 무효가 된다.

### device
학습은 **GPU를 쓴다**(`01_RULES.md` §9.5). GPU가 없으면 **CPU로라도 수행한다** — 입력이 64 실수 차원이라 CPU에서도 가능하다. 어느 쪽이든 **학습을 건너뛰지 않는다.**

## 3. 먼저 할 일 — $\sigma_t$ 격자를 측정해서 정한다

score model이 어느 노이즈 수준에서 좋아야 하는지는 **수신기가 실제로 질의하는 범위**가 정한다.

1. D1 testbed에서 `R2-ours-G`를 작은 $n$(예 64)으로 돌린다.
2. Module H가 매 반복 받는 cavity 정밀도 $\mathbf G$에서 유효 노이즈 수준 $1/g$의 **경험 분포**를 수집한다(반복·SNR·셀 전부 합쳐서).
3. 그 분포의 1–99 백분위를 덮는 **로그 등간격 격자**(점 20개 권장)를 $\sigma_t$ 격자로 확정한다.
4. 격자와 그 근거 분포를 `conf/results/sigma_grid.txt`에 남긴다. **이후 바꾸지 않는다.**

이 단계를 건너뛰고 임의 격자로 학습하면, 게이트를 통과해도 수신기에서 무의미하다.

## 4. 사다리 (순서대로, 위에서부터)

각 칸은 **score model의 파라미터화 또는 입력 표현**만 다르다. 순서는 고정이고, 건너뛰지 않는다.

| 칸 | 모델 | 바꾸는 축 |
|---|---|---|
| **L1** | **DSM / VE 스케줄**, noise-conditional MLP (Fourier time embedding + residual blocks), 입력 = 픽셀 도메인 $\mathbf H$ (2×$N_r$×$N_t$) | 기준선 |
| **L2** | **VP / DDPM $\epsilon$-prediction**, 동일 backbone | 파라미터화·스케줄 |
| **L3** | L1·L2 중 게이트 점수가 좋은 쪽의 backbone + **각도 도메인 입력**(공간 2D-DFT) | 입력 표현. 핸드오프 §9-2의 미결 질문 |
| **L4** | 배열 격자 위 **2D conv / 소형 U-Net** backbone, §L3에서 이긴 도메인 | 아키텍처 |
| **L5** | **Flow matching (rectified flow)**, Gaussian probability path에서 score 복원, §L3·L4에서 이긴 구성 | 학습 목적함수 |
| **L6** *(선택, 최하 우선)* | **VAE prior** — diffusion이 아니지만 "GMM/VAE로도 되지 않나"라는 리뷰어 질문의 답 | 비교군 |

### 칸마다의 재시도
각 칸은 **하이퍼파라미터 재시도 최대 3회**(학습률·폭·깊이·EMA). 3회 안에 게이트 미달이면 **다음 칸으로 간다.** 같은 칸을 4번째로 돌리지 않는다.

### 정지 규칙
L1→L6을 순서대로 시도한다. **전부 게이트 미달이면 거기서 멈추고, "이 데이터 예산에서 학습 score는 게이트에 도달하지 못한다"를 결과로 보고한다.** 이것은 실패가 아니라 findings다. 게이트를 낮춰서 통과시키지 않는다.

### 사다리 로그 (필수)
`conf/LADDER.md`에 **모든 시도를 append**한다. 실패한 시도도 전부 남긴다 — 이게 남아 있어야 나중에 "고르지 않았다"를 보일 수 있다.

```
[시각] 칸 | 시도# | 구성 요약 | 학습/검증 loss | GA | GB | GC | GD | 판정(PASS/FAIL) | 비고
```

## 5. 품질 게이트 (D1에서만, BLER 보기 전에 확정)

**D1 = 격자 GMM testbed.** 참 prior가 $K_{\rm true}=32\times32$ 격자 혼합으로 *정의*되어 있으므로 **정확 score가 폐형식으로 존재한다.** 그래서 게이트를 잴 수 있다. 이것이 D1을 버리지 않고 **계측기**로 남기는 이유다.

| id | 내용 | 기준 |
|---|---|---|
| **GA** | **Tweedie 자기무결성.** 학습 score로 만든 denoiser $\tilde{\mathbf h}+\sigma_t^2\hat{\mathbf s}$ 가 같은 모델의 직접 denoising 출력과 일치 | $\le10^{-6}$ |
| **GB** | **Denoising NMSE 초과율.** 전 $\sigma_t$ 격자에서 학습 score의 denoising NMSE가 **정확 score 대비 +5% 이내** | 전 격자 $\le$ +5% |
| **GC** | **Score 상대 오차.** $\mathbb E\|\hat{\mathbf s}-\mathbf s^\star\|_2/\mathbb E\|\mathbf s^\star\|_2$ | 전 격자 $\le0.15$ |
| **GD** | **Divergence 정확도.** D-14가 쓰는 Jacobian/divergence 추정의 상대 오차 | $\le0.20$ |

**PASS = GA·GB·GC·GD 전부 통과.** 하나라도 미달이면 그 시도는 FAIL이다.

> **기준값의 근거 [사전 등록].** exp_0923에서 one-shot(D13+D14) **인터페이스 자체의** 손실이 $T_p=2$에서 NMSE +13~19%였다. score model 자체의 오차가 그보다 훨씬 작아야 "인터페이스 탓"과 "네트워크 탓"을 구분할 수 있다. GB=+5%는 그 여유를 3배로 잡은 값이다.
>
> **이 네 숫자는 사용자가 실행 전에 바꿀 수 있다. 실행이 시작된 뒤에는 바꾸지 않는다.** 바꾸려면 `conf/DECISIONS.md`가 아니라 사용자 승인이 필요하다.

## 6. D2(주장용 testbed)에서의 선택 지표 — 정확 score가 없을 때

D2(`05_SPEC_testbed_D2.md`)에는 참 prior의 정확 score가 없다. 그래서 GB~GD를 잴 수 없다. 대신:

- **아키텍처·하이퍼파라미터는 D1에서 게이트를 통과한 구성을 그대로 쓴다.** D2에서 다시 탐색하지 않는다. (탐색하면 D2에서 선택하는 것이 되고, 그 선택이 무엇을 보고 이루어졌는지 설명할 수 없게 된다.)
- **GB′ (사전 등록 비교 지표):** held-out 표본에서 **동일 $\sigma_t$ 격자의 denoising NMSE**를 GMM prior와 diffusion prior에 대해 각각 잰다. 이것은 BLER 이전 단계의 공정한 비교이고, **그 자체로 논문에 실을 수 있는 결과**다.
- GB′는 **선택에 쓰지 않는다. 보고에만 쓴다.** D2의 arm 구성은 D1 게이트가 이미 정했다.

## 8. 금지

- BLER을 보고 사다리로 되돌아가기.
- 게이트 기준을 실행 중에 낮추기.
- diffusion에만 더 많은 학습 데이터·더 큰 예산 주기(§2의 동일 데이터 규약).
- D2에서 아키텍처를 다시 탐색하기(§6).
- 실패한 시도를 `LADDER.md`에서 지우기.
