6. **실행 순서의 `analysis` 가 ③④ 에서 죽는다 + 수용 명령이 C6 기본값과 어긋난다 — §1 에 명령 원문을 적어야 한다.** 위치: §1 실행 순서 "태그마다 `runner.py run …` → `analysis` → `run_manifest.py`", 수용 검사 행(명령 없음). 증거: PILOT16e4 §1(검토 1) "`runner.py analysis` 는 돌리지 않는다(표 A 가 파일럿 raw 에 없는 R2-ours-G 를 요구해 죽는다)" — ③ 은 3 arm, ④ 도 3 arm 이므로 같은 이유로 실패한다; `eval_accept.py --nr` 기본값 8 (`eval_accept.py:56`) 이라 C6 격자 검사는 `--nr 16` 없이는 `fit_S2v_Nr8_…` 를 찾아 FAILED 가 되고, 후보 3 개 검사는 코드가 **K ≥ 1024 만** 본다(`:138`) — 수용 (a) 의 "K ≥ 512 kron 은 후보 3 개" 는 스크립트가 검사하지 않는 문장이다. 고정안(문장 + 선행 코드 명세): 실행 순서를 "①② `analysis`; ③④ 는 analysis 없이 `run_manifest` → `eval_accept --ref-raw raw_S2vB16e4` → `pair_baselines.py`" 로; 수용 (a) 를 "K ≥ 1024 후보 3 개(스크립트) + K = 512 후보 3 개(§5 에 파일명·ll_val 로 기록)" 로; SVB16e4 §1 처럼 명령 원문을 적는다: `eval_accept.py --prior S2v --nr 16 --bstar kron --kron-K 4096 --ntrain 160000 --ll-val -58.45384925132457 --tag S2vB16e4:best:fef34e13133004fc:C6 --tag S2vB16e4last:last:9940812e5f7ab689:C6 --tag S2vPIL:best:fef34e13133004fc:C6 --tag S2vALD:best:fef34e13133004fc:C6 --ref-raw raw_S2vB16e4 --fits-dir results/gmm_fits_D2_S2vB16e4 --grid "full:16,32,64,128,256,512 kron:16,32,64,128,256,512,1024,2048,4096"` (③④ 는 14 arm 이 없으므로 `(bstar, kron_K, em_sec)` 동일 검사가 meta 에 있는지 — PILOT 선례에서 통과했다 — 스크립트 작성 시 확인), `recovery_ci.py --raw raw_S2vB16e4 --cell C6 --snrs -3` (+ 판정점), `frontier_ci.py --recovery …` 두 줄(best·last). `run_prior_eval.sh` 는 `--cell C2`·`raw_B16e4k` 가 박혀 있어(`:29, :57`) 그대로 못 쓴다 — 새 스크립트가 맞다.

7. **§5 의 학습 행이 사실을 다 적지 않는다: 학습은 재부팅으로 끊겨 두 세그먼트로 돌았고, b\* 의 세 재시작은 모두 C6B16e4 §6.5 의 정지 방식이다.** (a) 위치: §5 체크포인트 행("patience, aborted False"), §0 "학습 2483 epoch patience 정지". 증거(`logs/train_d2sx_S2vNR16_N160000_a1.log`): 세그먼트 1 머리말 `2026-09-28 01:34:34 KST` → epoch 1..2404; 세그먼트 2 머리말 `11:49:00 KST` → epoch 2405..2483 (`wall 1002 s`, 12.5 s/epoch), 정지 patience; 세그먼트 3 `12:16:49 KST` = GB′ 호출의 무동작 재개. 재부팅 전 best 는 @2394 (0.4521922), 최종 best @2463 (0.4519517, 차 2.4e-4) 는 **재개 세그먼트 안**이다. 재개는 규칙 안이고 로직은 연속 실행과 같게 설계돼 있지만(위 (6)), §5 는 "평가 전 고정 기록" 이므로 "재부팅(09-27 ~21:4x CDT)으로 epoch 2404 에서 중단 → 21:49 CDT 재개(체크포인트의 hp·optimizer·EMA·RNG 상태 복원) → 2483 patience; best 는 재개 뒤 @2463" 을 적어야 한다(HANDOFF_2026-09-27b 가 이미 재부팅을 기록한다). (b) 위치: §5 최종 b\* 행. 증거(npz): kron 4096 r0 120/110·재시드 5210, r1 127/120·5978, r2 98/90·5368 — 셋 다 `it_best = n_iter − 7..10` 이고 재시드 수천 회, 즉 C6B16e4 §6.5 가 사후에 발견한 "학습 우도 규칙으로 멈추고 검증 최고가 마지막 평가 시점" 이 **여기서는 사전에 보인다**(kron 2048 r2 도 141/100 재시드 124). 그리고 격자 꼭대기가 평평하다: 4096 −58.4538 vs 2048 병합 −58.5146 (**+0.061 nat**; C6 S2 는 +1.19) — "격자 끝에서 아직 오르는 중" 이라기보다 "2048 과 구분되지 않음". 고정안(§5 두 행에 사실 문장): "kron 4096 세 재시작 모두 train-ll 정지·검증 최고 = 마지막 평가(§6.5 형 캐비엇, 사전 기록); 2048 대비 +0.061 nat" — 이러면 §6 에서 이 캐비엇이 "사후 발견" 이 아니라 "사전 기록" 이 된다.

8. **판정 2 의 다중성·앵커 규칙이 "12 중 k" 를 약한 baseline 이 채우게 만든다 — 개수 문장 옆에 사전 정의된 "가장 강한 baseline" 판독을 하나 두어야 목표 문장("모든 baseline 과 멀어진다") 이 검증 가능해진다.** 위치: §1 판정 2·판독 행, §2 둘째 표. 문제: C6 S2 실측(−3 dB 실패, `pair_PILNR16`·`tables_D2_NR16B16e4`) 은 R0 376 / R1 0.259·2560 ≈ 663 / R3 0.416·2560 ≈ 1065 / R4-llr 0.841·2560 ≈ 2153 / R4-scvamp ≈ 814 / bstar-pilot 240 / ALD 249 / ALDv 222 / gmm32 230 / b\*-scalar ≈ 207 / R2 ≈ 294 대 V1 53 — 𝔅 의 절반은 (i) 가 사실상 예정돼 있고 R_X 도 1 근처다. "12 중 k" 는 그래서 정보량이 약한 문장이고, 반대로 정보가 있는 것은 **가장 강한 X 하나에 대한 R_X 와 CI** 다. 그런데 "가장 강한 X" 를 결과 뒤 고르면 사후 선택이다. 고정안(문장만): §1 에 규칙 한 줄 — "X\* = 𝔅 ∪ {b\*} 중 −3 dB 실패 수 최소인 arm(동률이면 이름순; 결과 전에 정해지지 않는 결정적 규칙) 에 대해 R_{X\*}(−3 dB) 와 90% paired CI 를 '가장 가까운 baseline 대비 회수율' 로 보고; 원고의 '모든 baseline 과 멀어진다' 문장은 **k = |𝔅| + 1 이고 R_{X\*} 의 CI 하한 > 0** 일 때만 쓴다" + §3 에 X\* 예측(예: "X\* = ALDv-pilot 또는 gmm32; R_{X\*} 0.5–0.9"). 또 R_X 2차의 "X 의 판정점 3 점 합" 은 X 가 (iv)(판정점 < 3) 이면 정의를 적어야 한다 — "있는 판정점의 합, 점 수를 표기; 0 개면 정의하지 않음".

## B. 권고

9. **ΔR (S2 C6 대비) 의 "같은 셀·예산" 문장에 세 가지 비대칭을 미리 적을 것.** (a) NR16B16e4 의 V1 은 **§3d 시행 2(기울기 클리핑 1.0)** 가중치(`_fb2_best`) 이고 S2v 는 시행 1(클리핑 없음) — 같은 동결 레시피의 사다리 규칙 안이지만 학습 조건이 같지 않다; (b) S2 C6 는 σ 격자 `NR16` 을 1e4 적합에서 **재사용**했고 S2v 는 자체 측정(`S2vNR16`, 상한 0.4994 대 0.4915) — 학습 잡음 범위가 다르다; (c) 두 b\* 의 수렴 캐비엇(위 7(b)) 이 방향은 같고 정도는 다르다(+1.19 vs +0.061 nat). §1 ΔR 행에 "비짝·PID 다름" 옆에 (a)(b)(c) 한 줄씩 — "ΔR 세 갈래 문장은 이 차이를 포함한 채널+학습 조건 차이의 합" 으로 못 박으면 리뷰어 질문이 사라진다.

10. **§0 의 사실 문장 셋.** (a) "(기존 S2 스트림과 같은 경로 각)" 은 같은 rng 를 넣었을 때의 코드 성질이지 스트림의 성질이 아니다 — PID 9 라 학습·테스트 스트림의 각은 S2 와 **다르다**(§0 마지막 줄이 스스로 그렇게 적는다). "같은 rng 상태에서는 S2 의 (L, θ, φ, ψ) 를 그대로 뽑은 뒤 창을 뽑는다(코드 성질); 스트림은 PID 로 다르다" 로. (b) "testbed 검사(이전 세션 값 … 1.001, 0.62, 0.39)" 는 파일이 없다(`results/testbed_S2v.txt` 는 main·worktree 어디에도 없고, S2v 용 testbed 스크립트도 코드에 없다 — grep). §4 의 "스크립트 재생성" 에 스크립트 이름과 검사 항목을 적을 것(예: `testbed_s2v.py`: 정규화 E‖H‖²/(NrNt), 블록 안 수신 소자 전력 CoV, 앙상블 Rr 대각 퍼짐, 창 폭·시작 분포의 경험 히스토그램 = U{4..16}·U{0..Nr−w}); 기존 `d2.py:305-322` 의 "해석적 C_ens 대 MC" 검사는 S2v 에서 **설계상 DISAGREES** 이므로 그 항목은 빼거나 "Rr 미정의" 로 표기. (c) "학습 2483 epoch … S2 C6 보다 val 이 훨씬 높다(모델이 다르므로 척도 비교 아님)" — 맞지만 "다르므로" 의 뜻은 **데이터 분포**가 달라서(DSM 손실의 바닥이 prior 마다 다름) 이지 모델(같은 hp)이 달라서가 아니다. 한 단어 정정.

13. **σ 격자 측정의 테스트 시행 노출을 SVB16e4 §1 수준으로.** 머리말은 "σ 격자 측정(Gaussian 수신기, ν_q 만)" 이라 적었다 — 파일은 `C6 n = 64 trials/point` 즉 **테스트 시행 0..63** 을 M-ours-G 인터페이스로 한 번 돌렸다(BLER 미기록). SVB16e4 §1 셀 행처럼 "예외: … 시행 0..63, ν_q 만, 헤드라인·D3 관례" 를 §1 에 옮길 것(머리말은 원고에 안 들어간다).

14. **§1 (d) 의 genie 비트 동일 검사 방향.** ②③④ 의 R5-genie 를 ① 과 대조하려면 ① 이 먼저 끝나야 한다 — 실행 순서 ①→②→③→④ 와 맞지만, 스크립트는 ① 이 ABORT 되면 ②~④ 를 시작하지 않아야 한다(참조가 없다). 그리고 ③④ 의 `eval_accept --ref-raw raw_S2vB16e4` 는 `--ref-arms R5-genie` 기본(4 키)이면 충분; `--ref-arms all` 은 ② 에만(V0/V1/V4/V4b 외 10 arm 비트 동일 — SVB16e4 §6 추가 확인 선례).
