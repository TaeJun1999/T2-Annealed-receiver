(b) 시험은 고정 δ 인데 S2d prior 는 δ 를 모르는 **혼합 prior** 라, δ 를 아는 prior(각도별 정합 학습) 보다 nuisance 비용을 낸다 — 두 prior 에 공통이므로 RB 는 공정; "δ 추정·각도별 재학습은 범위 밖" 을 §2 범위 문장에. (c) "보지 못한 표류에 대한 일반화가 아니다" 는 이미 있다 — 좋다.

19. **S2d 생성기·selftest.** `selftest_s2d.py` 는 (1) 구 prior 3 × 배열 2 에서 `sample_vecs`·`sample`·`sample_paths` 와 rng 상태 동일(9c0ca1f4 `git show` 원본과 대조), (2) S2d 의 th = S2 의 th + δ(블록 공통, 0 ≤ δ < 30°, 평균 ≈ 15°), ph·al·L 동일, (3) PID 10 유일, 전력, 새 스트림 — 내가 재실행해 OK. `D2Gen.drift` 는 인스턴스 속성이라 다른 prior 의 인스턴스에 영향 없음; `.rot` 는 그 위에 더해진다(회전 시험은 `--prior S2` 라 S2d 생성기에 `.rot` 가 설정될 일은 없다).

20. **`--train-prior` 경로의 나머지(MISMATCH 메모 13 재확인).** V1 의 C/cbar/eh2 · R2·R0·R1·R4 의 Cs · b\*·gmm32 · em_sec 은 모두 태그 fits 디렉터리에서; genie 의 `nuE=cbar`·`eh2` 초기화는 저장되지 않아 4 키 비트 동일 전제는 유지된다. σ 격자 값은 out-of-grid 카운터에만 쓰인다(수치 경로 아님).

21. **RB-0 (RMX0) 의 정체.** S2d 학습 prior 를 정적 S2 시행에 놓는 것이므로 MISMATCH 형(학습 S2d → 평가 S2)이다 — MMs2cs2 등과 같은 열에 놓고 읽어도 된다(보고 전용).

22. **GB′.** `s2d_post.log` 는 12:13 KST 에 `run_d2_sx.py --prior S2d … --fallback 1` 이 재개 없이(1368 ep 유지) GB′ 단계로 들어간 것까지만 있고 결과 줄은 아직 없다(GPU 1 1.7 GB 점유 = 실행 중; tmux `s2dgb`). §5 에 S2V §5 형식(GMM b\* = kron 4096 확인, GPU 대 CPU 상대차, 비 min/max/median, equal_budget=True)으로.

23. **파일럿.** S2d 의 Rt = S2 의 Rt(송신각 불변) 이므로 "S2 와 같은 파일럿 행렬" 은 구조적으로 참이고, 실행 prior 가 S2 라 어차피 `make_pilots(S2)` 다 — 두 이유를 §0 에 나란히 적으면 "S2d 로 파일럿을 다시 짰어야 하지 않나" 가 사라진다.

24. **ROT 종료 뒤 CPU 공유.** S2V BLER(≈ 9–10 h)와 ROTMIX(≈ 2.5 h)가 같은 CPU 를 쓰면 둘 다 비용 추정이 틀린다 — 순서를 §4 에(HANDOFF 는 C → B′ 순서).
