## B. 권고

2. **런너 쪽 같은 검사 한 줄 (패치 보강).** `runner_train_prior.diff` 의 MISMATCH 출력 직전에 `p = os.path.realpath(A.fit_path("D2", run_prior, 8, "full", 32, a.ntrain)); if not os.path.basename(p).startswith(f"fit_{mis}_"): sys.exit(...)` — 태그 fits 디렉터리가 선언한 학습 prior 의 파일로 풀리지 않으면 거부. 이러면 "V1 만 불일치, GMM/Chat 은 정합" 인 반쪽 불일치가 런너에서 막힌다(지금은 eval_accept 의 b\*/ll_val 검사에서만 잡힌다 — 다행히 8 쌍 모두 학습·평가 b\* 의 ll_val 이 다르므로 잡히긴 한다). `--train-prior` 에 `choices=list(C.PID)` 도 붙일 것(지금은 오타가 guard 의 "must name the checkpoint's own prior" 로 거부되긴 한다). 패치 나머지는 옳고 최소다: legacy `d2sx_N160000_a1.pt` 도 `prior='S2'` 키를 갖고 있어(torch.load 확인) 등록된 3 쌍이 거부되지 않으며, `ck_prior == run_prior` 인 정합 실행에 플래그를 붙이면 거부되고, `changed` 목록 추가로 `--tag` 필수, smoke 에도 같은 guard 가 걸린다.

3. **출처(provenance) 한 줄.** raw meta 에는 `stagec_ckpt`(절대경로)·`stagec_ckpt_id`(sha·role)·`em_sec_note`(fits 디렉터리 절대경로: "sum of 'sec' over 13 fit files in …/gmm_fits_D2_<TAG>")·`bstar`·`ll_val|*`·`em_sec` 이 남으므로 사후 증명은 가능하다(ckpt 파일의 `prior` 키 + 링크 디렉터리 + em_sec 지문). 그러나 "학습 prior" 문자열 자체는 어디에도 없다: run_manifest 의 `stagec_checkpoint.rung` 은 `D2SXS2c160000` 처럼 prior 를 담지만 legacy 는 `D2SX160000` 이다. 고정안: `run_manifest.py` 의 ckpt dict 에 `train_prior=st.get("prior")` 한 항목(같은 코드 커밋에 포함). 원하면 등록 §1 에 "학습 prior 의 사후 증명 = manifest `stagec_checkpoint.train_prior` + `em_sec_note` 의 디렉터리 + §1 검사" 라고 적는다.

4. **쌍 선택의 방어선.** §1 은 8/20 순서쌍을 "예산상(D2 허브)" 로 정당화하지만 쌍당 CPU 10–20 분이면 20 쌍도 ≈5 h 이고 GPU·학습이 없다. 정합 결과를 모두 본 뒤의 선택(공개됨)이라 적대적 리뷰어의 첫 질문은 "왜 SV8e↔D3·SV8e↔UMi28·D3↔38.901 이 없나" 다. 선택지: (가) 20 쌍 전부(스크립트 DS 표 12 행 추가, 링크 12 디렉터리; 라벨 수·다중성 문장 갱신) — **사용자 결정**; (나) 지금 8 쌍을 유지하되 §1 에 "나머지 12 조합은 이 등록으로 **나중에 추가하지 않는다**(추가하려면 새 등록·새 공개)" 한 문장. 어느 쪽이든 §6 은 "8(또는 20) 개 pair 파일·무효 기록이 모두 있을 때만 쓴다"(PILOT v2 선례 문장) 를 §1 실행 행에 넣는다.

5. **예측 3 의 채점 규칙.** "D2-U28·U28-D2: (i) 아님 둘 다" 는 (iv) UNDECIDED 도 적중이 된다 — 방향 예측이 검정력 미달로 "적중" 하면 리뷰어가 문제 삼는다. 고정안: "(ii) 또는 (iii) 이면 적중, (i) 이면 빗나감, (iv) 는 채점 불가(둘 중 하나라도 (iv) 면 항목 무효)". 예측 1·2·5·6 은 (i) 여부라 이분 그대로 좋다.

6. **채널 추정 NMSE 보고 행.** 불일치 실험의 자연 지표는 채널 추정 NMSE 다(prior 가 틀렸을 때 가장 먼저 움직이는 양). `pair_mismatch.py` 에 `pair_cross.py:95-97` 의 SNR 별 nmse@16 중앙값 출력(R2-mis, bstar-mis, V1-mis, 정합 R2, b\*, V1)을 그대로 붙이고 §1 보고 전용에 한 줄. 판정 아님. 같은 자리에 "격차 보존율 = MM 격차 / 정합 `b*→V1` 격차" 를 숫자만 적는 것도 값싸다(검정 없음; 두 격차는 이미 출력됨).

7. **불일치의 범위를 한 문장으로 못박기.** 수신기의 prior 만 학습 prior 이고, (i) 파일럿 행렬은 평가 prior 의 ensemble 고유벡터(`common.make_pilots(testbed, P_te)`; base raw 와 같아야 시행이 짝지어진다), (ii) 잡음 분산 σ² 은 알려진 값, (iii) b\* 의 K 선택도 학습 검증 우도로 고정(배치 데이터로 재선택하지 않음) 이다. 리뷰어가 "송신기가 평가 채널의 2차 통계를 안다" 를 물을 것이므로 §1 불일치 구성 행에 (i)–(iii) 을 적는다. 또 R2-mis(학습 Chat 의 Gaussian) 옆에 정합 R2 가 있으므로 "Gaussian 조차 불일치 비용을 낸다" 를 읽을 수 있다 — 보고 전용 pair `R2-mis → R2-ours-G` 를 PAIRS 에 넣을지(6 번째 보고 pair, 다중성 문장 32→40) 는 선택.

8. **스크립트 소소한 것.** (a) `[ -d $BASE ]` 를 실행 전에 — 없으면 15 분 뒤 eval_accept "no reference point" 로 무효가 된다.
