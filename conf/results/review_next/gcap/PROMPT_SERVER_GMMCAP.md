# E2′ — UMi 32×4 GMM 용량 확인 (tag 제안: U28NR32GCAP)

먼저 `PROMPT_SERVER_COMMON.md` 를 끝까지 읽는다.

## 목적

제출판은 3GPP UMi 28 GHz 32×4 결과를 주요 그림에 올린다. 이 셀의 GMM b\* 는 kron K = 4096 으로 격자 끝 (4096 에서 멈춤) 이고, 기록의 Q-K 한정어는 "[K 상한 민감: 외삽 불가]" 다. 심사자가 "GMM 용량이 부족해서 진 것 아닌가" 라고 물을 수 있으므로, K 를 한 단계 늘리고 기존 fit 의 수렴 상태를 확인한다. 기록상 K 2048 → 4096 은 판정점 실패 합을 960 → 958 로만 바꿨다 (학습 prior 599, 차이 359; RESULTS §21.4 (e)). 따라서 큰 변화를 기대하는 실험이 아니라, 주요 적용 결과의 비교 대상을 한 단계 더 확인하는 실험이다. 결과가 이득을 줄이면 그 수치가 원고에 들어간다.

## 셀 (기록상 값 — 실행 전에 manifest 와 대조)

- UMi28 C9, tag `U28NR32B16e4`: N_r 32, N_t 4, T 16, T_p 4, QPSK, K_b 42, N′ = 1.6×10⁵ training channels + 5000 validation channels.
- 학습 prior V1: `U28NR32B16e4` 의 `_best` 체크포인트 (고정, 재학습 없음).
- 기존 b\*: kron K = 4096, 재시작 3, tol 정지 24/24.
- SNR 격자 −12/−9/−6/−3/0/+3/+6 dB, test trial 0..2559, 판정점 −3/0/+3 dB.
- 기존 판정점 실패 합: b\* 958, V1 599, genie 127. 표 B `b* → V1` 391:32, (i). SNR@0.1 격차 +2.29 dB [+1.98, +2.61].

## 실행 순서

1. 선택된 K4096 fit 의 best-validation 상태와 fit log (반복별 train/validation LL, 종료 사유) 를 확인하고 기록한다.
2. 그 best-validation 상태에서 같은 데이터로 EM 을 정확히 50회 더 돌린다. 이 continuation 에서는 LL 증가량 기준의 조기 종료를 끈다. 10회마다 validation LL 을 기록하고, 최초 상태를 포함한 best-validation 상태를 보존한다. 50회는 작업 예산이지 수렴의 정의가 아니다. 수치 이상으로 멈추면 실제 완료 반복 수, 원인, fit 상태를 기록하고, 그것을 "50회 완료" 나 "수렴" 으로 분류하지 않는다.
3. kron K = 8192 를 기존 규칙 (재시작 3, 최대 반복, validation 선택) 으로 한 번 적합한다. 먼저 짧게 돌려 시간·GPU 메모리를 재고, 전체 적합이 10/18 안에 끝나지 않으면 사용자에게 알린다. 종료 사유를 수렴 / 예산 소진 / 수치 이상으로 구분하고, training LL 이 한 번 감소한 것만으로 수렴 종료가 발동하지 않도록 종료 조건을 manifest 에 적는다.
4. 후보 (기존 K4096, continued K4096, K8192) 중 validation LL 이 가장 높은 것을 최종 b\* 로 고르고 동결한다. test BLER 은 보지 않는다.
5. 최종 선택이 기존 K4096 과 같으면 test 평가 없이 끝낸다. 기록 문장: "검사한 범위 (continuation 50회, K 8192) 에서 validation LL 이 기존 K4096 을 넘지 못했다."
6. 최종 선택이 다르면 그 fit 을 새 b\* arm 으로 7-SNR × test 0..2559 에서 평가한다. V1·genie 등 기존 arm 은 기존 raw 를 재사용하되, 같은 시행임을 확인하는 청크 하나를 다시 돌려 비트 동일을 확인한다. 평가 시간을 먼저 추정하고 10/21 안에 끝나지 않으면 사용자에게 알린다.

## 보고할 것

- 표 B `b*(새) → V1`: 판정점 (기존 자동 규칙으로 다시 정함), 점별 a:b, 라벨, ΣF (b\*, V1, genie), R, SNR@0.1 격차 [90% paired].
- 기존 K4096 수치를 같은 표에 나란히 둔다.
- 선택된 fit 이 다시 격자 끝 (K8192) 이면 상한 한정어를 유지한다. "용량 문제가 해소됐다" 고 쓰지 않고 "검사한 family·K 범위" 를 쓴다.
- 최종 fit 의 경로와 SHA-256 (E4 비용 측정이 같은 fit 을 써야 한다).

## 하지 않는 것

- 새 GMM family (각도 대각, circulant, Toeplitz 등). 전용 site 경로가 필요하고 이번 일정에 들어가지 않는다. 등록 문서에 "평가한 family 는 full·Kronecker 뿐" 이라고 적는다.
- UMi 16×4, D2 등 다른 셀로의 확장.
- test BLER 을 본 뒤의 fit 재선택, K 추가 확장.
