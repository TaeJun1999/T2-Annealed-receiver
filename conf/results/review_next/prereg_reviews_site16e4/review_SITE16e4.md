## MUST (동결 전 반드시 고친다)

### MUST-1. §2 채우는 규칙 3 번째 항목 — 둘째 문장을 비울 수 있는 탈출구는 사용자 결정 "결과가 어떻든 문장을 넣는다" 와 어긋난다; 게다가 n/a·`>=` 가지는 이미 닿을 수 없다

- 위치: §2 "채우는 규칙" 3 번째 글머리 (`gain` 출력이 위 꼴이 아니면 … 둘째 문장을 채우지 않고 …).
- 문제: (a) `gain` 의 kind 는 두 arm 의 **주변 BLER 만으로 이미 'ok' 로 정해져 있다** — `snr_at` 은 첫 하향 교차를 찾는데 V1·V4 모두 −3 dB 에서 0.145/0.154 > 0.1, 0 dB 에서 0.034/0.037 < 0.1 (TABLE A :71–72) 이므로 두 arm 다 격자 안에서 교차한다 (`exp_0925_analysis.gain` :57–71). 따라서 "n/a"·"한쪽 경계 `>=`" 는 **도달 불가능**하고, 이를 열린 경우처럼 적는 것은 (b)(c) 류의 공개 누락이다. (b) 남는 가지 "censored replicates > 0%" 는 형식상 도달 가능한데 (실제로는 0.145 → 0.1 이 bootstrap SD ≈ 0.007 의 6 배 밖이라 사실상 0%), 이 가지가 열리면 사용자가 고정한 둘째 문장이 원고에서 빠진다 — "결과를 본 뒤 넣을지 고르지 않는다" 를 규칙 하나로 비켜 가는 셈이다. 표 B 자체는 censored % 를 찍으면서 구간을 내므로 문장을 비울 이유도 없다.
- 고침 (3 번째 글머리를 통째로 교체):
  > - `gain` 의 kind 는 주변 BLER 로 이미 'ok' 로 정해져 있다 (V1·V4 모두 −3 dB BLER > 0.1, 0 dB BLER < 0.1 → 두 arm 다 격자 안 교차; n/a·`>=` 꼴은 나올 수 없다). 둘째 문장은 **항상** 채운다. 출력의 `censored replicates` 가 `0%` 가 아니면 그 % 를 §6 과 사용자 보고에 적되 문장은 그대로 채운다.
- §3 항목 0 (이미 정해진 것) 에 "SNR@0.1 격차의 kind = ok (n/a 불가)" 를 추가한다.

## SHOULD

### SHOULD-1. 혼합 결과 (+3 dB 가 V4 쪽 유의) 는 **실제로 닿을 수 있는** 결과다 — 머리말에 겹침 수로 공개하고, 동결 전에 사용자에게 한 번 알린다

- 위치: 머리말 (d), §2 "혼합" 글머리, §3.
- 근거 (산술): 불일치 쌍 수 D = F_V4 + F_V1 − 2c, c = 두 arm 이 **함께** 실패한 블록 수. 그러므로 (d) 의 D 임계값은 c 로 바꿔 쓸 수 있고 그쪽이 훨씬 읽기 쉽다:
  - −3 dB (a − b = +23): V1 쪽 유의 ⟺ D ≤ 125 ⟺ **c ≥ 320** (V1 실패 371 중 86 % 이상이 V4 실패와 겹침)
  - 0 dB (a − b = +8): V1 쪽 유의 ⟺ D ≤ 12 ⟺ **c ≥ 86** (V1 실패 88 중 86 이상)
  - +3 dB (b − a = +8): V4 쪽 유의 ⟺ D ≤ 12 ⟺ **c ≥ 19** (V4 실패 21 중 19 이상)
  - pooled (보고 전용, a − b = +23): p < .05 ⟺ pooled D ≤ 125 ⟺ Σc ≥ 437 (최대 480)
  같은 가중치에 site 만 다른 두 arm 이라 V4 의 +3 dB 실패 21 개가 거의 전부 V1 의 실패에 포함될 수 있다 → 혼합 ((i) 또는 (iii) + "+3 dB 반대쪽 유의") 은 열린 결과다. 현 규칙 (라벨·첫 문장은 그대로, §6 에 명시) 은 결과 뒤 선택을 남기지 않으므로 수용 가능하지만, 원고에 "fails less … at two of the three" 만 남고 세 번째 점의 반대 유의가 원고에 안 실리는 것은 **사용자가 결과 전에** 알고 택해야 한다.
- 고침: (1) 머리말 (d) 끝에 위 c 환산 네 줄을 추가. (2) 머리말에 한 줄 추가: "**혼합 결과는 도달 가능**하다 (+3 dB 에서 c ≥ 19/21); 이 경우도 §2 의 문장은 라벨대로이고 추가 문장은 없다 (사용자 확인: 동결 전)". (3) 동결 전 사용자에게 이 한 가지만 묻는다 — 답이 없으면 현 규칙 유지. (4) §3 항목 2·3·4 에 괄호로 c 조건을 덧붙인다 (예: "2. −3 dB: V1 쪽 유의 (c ≥ 320/371)").
