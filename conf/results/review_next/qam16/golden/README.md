# 정답 사례: QPSK·16-QAM 변조와 블록 크기 K

명세(위임 메시지)와 교과서 수준의 QAM 성질만으로 만들었고, 구현 코드(`Demo/`, `conf/code/`, `~/t2_wtE5/`, `~/t2_wtE3/`)는 열지 않았다.
모든 검사는 라벨 규약과 무관하다. 어느 비트가 실수 축인지, 0이 +인지, 비트 순서가 어떤지는 결과에 영향을 주지 않는다.

## 파일
- `golden_qam16.json`: 사례별 입력, 기대값, 계산 과정, 허용오차
- `golden_qam16.py`: 참조 구현과 검사 함수, 자체 시험(`_selftest`)
  - `check_K(m, Ns, K, nu=6)`
  - `check_constellation(points, labels, atol=1e-12)`: `points[k]`가 `labels[k]`를 실어 나른다. labels는 정수 `(M,)`이나 0/1 비트 행렬 `(M, m)` 둘 다 받고, 점 순서는 상관없다.
  - `check_roundtrip(modulate, hard_demod, m, atol)`: 구현의 변조·경판정 함수를 그대로 넣는다. 비트 순서는 구현이 쓰는 순서를 따른다.

## 구현에 적용하는 법
```python
import sys; sys.path.insert(0, "<이 폴더>")
from golden_qam16 import check_K, check_constellation, check_roundtrip
check_K(4, 48, K_impl)                              # ['ok'] == True
check_constellation(points_impl, labels_impl)       # ['ok'], ['fails']
check_roundtrip(mod_impl, lambda y: (llr_impl(y) < 0).astype(int), 4)   # LLR 부호 규약에 맞춰 < 또는 >
```
자체 시험: `taskset -c 6 ~/miniforge3/envs/torch/bin/python -I golden_qam16.py`. 실행하면 `ALL GOLDEN CHECKS PASSED`가 나오고 0.2초쯤 걸린다.

## 사례와 기대값

| ID | 입력 | 기대값 | 계산 |
|---|---|---|---|
| C1 | (m, Ns) = (2, 48), (4, 48) | K = 42, 90 / 부호 비트 수 96, 192 | Ns = 4·(16−4) = 48. K = Ns·m/2 − 6이고, 2(42+6) = 96, 2(90+6) = 192다. K/Ns = 0.875, 1.875, 실효 부호율 = 0.4375, 0.46875 |
| C2 | 16-QAM | 점 집합 {±1,±3}+j{±1,±3} 곱하기 1/√10, Es = 1, d_min = 2/√10 = 0.6324555320336759, Es/m = 0.25, 에너지 껍질 {0.2: 4, 1.0: 8, 1.8: 4}, 최대 1.8 (2.55 dB), 축 판정 경계 0, ±2/√10 | 축마다 a²의 평균 = (9+1+1+9)/4 = 5, 두 축을 더해 10, 곱하기 1/10 = 1. 껍질로 검산하면 (4·0.2+8·1+4·1.8)/16 = 1 |
| C3 | 16-QAM 라벨 | 최근접 쌍 24개가 모두 해밍 1(위반 0), 축 분리 2+2, 해밍 행렬 H = g(\|Δr\|)+g(\|Δi\|)와 g = [0,1,2,1]이 256칸 모두 일치, 해밍 분포 {1: 32, 2: 48, 3: 32, 4: 8} | 최근접 쌍 수는 4행·3 + 4열·3 = 24다. 서로 다른 2비트 라벨 넷이 인접할 때마다 1비트씩 다르면 4-사이클 00-01-11-10을 돈다. 그래서 양 끝 레벨(Δ=3)은 1비트, Δ=2는 2비트 차이다. H=1인 32쌍은 d_min 거리에 24쌍, 3·d_min 거리에 8쌍이다 |
| C4 | 구현의 mod/demod | 오류 0. 시행 수는 16-QAM이 무잡음 16, 0.99·d_min/2 섭동 128(8방향), 이웃 쪽으로 51% 이동 48, 바깥으로 밀기 16이고, QPSK가 4 / 32 / 8 / 8 | (b) 판정 영역은 반폭 d_min/2인 정사각형을 포함한다. (c) 51% 이동하면 이웃의 라벨이 나오고 원래 라벨과 정확히 1비트 다르다. (d) 바깥 영역은 무한히 열려 있다 |
| C5 | QPSK | 점 (±1±j)/√2, Es = 1, d_min = √2, Es/m = 0.5, 최근접 쌍 4개 모두 해밍 1, 점마다 이웃 2개 | 모든 점에서 \|s\|² = 2/2 = 1 |

경계 조건:
- B1 이웃 수: 모서리는 2(4점), 가장자리는 3(8점), 안쪽은 4(4점)이다. 모서리 4, 가장자리 4·(4−2) = 8, 안쪽 (4−2)² = 4로 나온다.
- B2 평균 에너지: QPSK와 16-QAM 모두 1이고 차이는 2e-12 이하다.
- B3 K 경계:
  - 최소 블록은 QPSK가 Ns = 7(K = 1), 16-QAM이 Ns = 4(K = 2)다.
  - Ns·m/2 = 6이면 K = 0이라 거부한다.
  - Ns·m이 홀수이면 정수 K가 없어 거부한다.
  - 흔한 오답도 거부한다. 꼬리를 빠뜨리면 K = 48, 96이 되고, 꼬리를 부호 비트 6개로 세면 (Ns·m − 6)/2 = 45, 93이 된다.
- B4 판정 경계: 0.99·d_min/2 안이면 라벨이 그대로이고, 0.51을 넘으면 이웃 라벨로 바뀌며, 바깥으로 멀리 밀어도 라벨이 그대로다. 정확히 d_min/2에서 생기는 동점은 구현마다 정하는 것이라 시험하지 않는다.
- B5 거부해야 하는 입력:
  - 축별 자연 이진 라벨: Gray 위반 8(행 4 + 열 4), 해밍 행렬 불일치 160/256. 1차원 오차 e가 0, +1, −1인 순서쌍이 각각 8, 4, 4개이므로 일치는 64+16+16 = 96이고, 불일치는 256 − 96 = 160이다.
  - 라벨 중복: 전단사 실패
  - 정규화 누락(×√10): Es = 10, 점 집합 실패
  - complex64: 1e-12에서는 실패하고 1e-6에서는 통과
  - M = 15: 실패
  - 정규화하지 않은 격자의 판정 경계 0, ±2를 쓰는 demod: 무잡음에서 12개 심볼 오류(안쪽 4점 말고 전부)

## 허용오차
- 정수(K, 개수, 해밍)는 정확히 같아야 한다.
- 부동소수는 complex128 기준 절대오차 1e-12다. 구현이 complex64이면 1e-6을 쓰고 float32라고 보고한다.
- 최근접 이웃은 측정한 거리가 아니라 격자 지표(\|Δr\|+\|Δi\| = 1)로 정한다. 그래서 거리 오차가 이웃 판정에 번지지 않는다.

## 확인한 것
- 4×4 격자의 Gray 라벨링을 전수 탐색했더니 정확히 384개였다. 이는 Re 비트 쌍을 고르는 6가지 × 축마다 1차원 Gray 8가지 × 8가지 = |Aut(Q4)|와 같다. 384개 모두 `check_constellation`을 통과했다. 따라서 16-QAM에서는 축 분리와 해밍 행렬이 "최근접 이웃 Gray + 전단사"에서 따라 나오고, 별도 가정이 아니다.
- 규약 둘(TS 38.211 형태, 축별 00-01-11-10)과 QPSK·16-QAM을 섞은 200개 무작위 대칭 변형(비트 치환·반전, 90° 회전, 켤레, 점 순서 섞기, 비트 행렬 입력)이 모두 통과했다.

## 남은 불확실성과 범위 밖
- 참조 규약 `3gpp`의 식(TS 38.211 §5.1.3–5.1.4)은 기억으로 썼고 원문과 대조하지 않았다. 검사는 규약과 무관하므로 판정에는 영향이 없다.
- 하지 않은 것:
  - 부호기 자체(임펄스 응답, 자유 거리 10): 탭 순서와 출력 순서가 규약에 따라 다르다. 필요하면 "출력 비트 수 = 2(K+6)"와 "전부 0 입력 → 전부 0 출력"부터 넣을 수 있다.
  - LLR 값 검사: 부호와 척도 규약이 명세에 없다. max-log |LLR|·σ²는 규약과 무관하게 정할 수 있는데, 무잡음 16-QAM에서 모서리 점은 {1.6, 1.6, 0.4, 0.4}, 가장자리 점은 {1.6, 0.4, 0.4, 0.4}, 안쪽 점은 {0.4}×4다(참조 성상으로 수치 확인). 명세가 정해지면 사례로 추가할 수 있다.
