4. forward/VJP 및 H의 정의와 센 위치

forward:
- bench_cost.py:237–240에서 count_forward가 1을 더하고 원 함수를 부른다. :282에서 감싼 대상은 rx.prior.model.net.forward다. ScoreModel의 __call__나 denoise 횟수를 forward로 대체한 것이 아니다.
- score.py:1119의 f는 tweedie_real이고 :1120에서 jacrev(f)(x), :1121에서 평균을 위한 f(x)를 각각 실행한다. tweedie_real(:589–592) → score_real(:404 이하) → raw(:382–385) → net 호출이다.
- 따라서 확인한 16개 캐시 미스 질의에서 backbone이 2회씩 실행되어 32. denoise 호출은 16.
- _matrix_site가 denoise_full을 호출하는 위치는 Demo/t2_gmm.py:112–113. ScorePrior._eval(:1111–1113)의 캐시가 동일 (q,nu)를 돌려주므로 이것 때문에 backbone 2회가 더 추가되는 것은 아니다.
- denoise 호출 16과 캐시 미스 16은 개념이 다르다. bench는 캐시 미스 수를 별도 저장하지 않는다. golden/golden_cost.md:114–123의 독립 n_query·jacrev 관측은 확인한 블록에서 16이다. 같은 질의가 반복되면 캐시로 forward/VJP가 줄 수 있으므로 모든 미래 블록이 반드시 32라는 주장은 하지 않는다.

VJP:
- bench_cost.py:283에서 torch._functorch.eager_transforms._vjp_with_argnums를 감싼다. :242–264에서 반환 pullback을 다시 감싸 실제 cotangent의 숨은 batch 폭을 읽고 성공한 pullback별 폭을 저장한다.
- :385–386의 vjp=sum(vjp_widths)는 논리적 스칼라 방향 수, vjp_batches=len(vjp_widths)는 Python pullback 호출 수다. 구성값 16·2N을 카운터에 주입하지 않는다.
- 저장 출력: D2 VJP=1024, U32=4096; pullback 호출은 둘 다 16. 이는 각각 64·16, 256·16 방향에 해당한다. VJP=16이라고 보고하거나 하드웨어 backward kernel 1024/4096회로 해석하면 안 된다.
- measure.log:1275–1277의 분석적 확인은 dim=3/chunk=None → [3], dim=5/chunk=2 → [2,2,1], dim=2/chunk=1 → [1,1]을 관측하고 Jacobian도 확인했다. private torch API에 의존하므로 버전 변경 시 다시 확인해야 한다.

module H와 시간:
- score H = prior.denoise와 rx._matrix_site의 대응 호출 시간 합(bench_cost.py:284–285,295–299). H 호출 수는 denoise 진입 수.
- GMM H = prior.ep_site 전체(:287).
- SBL H = SparsePrior.ep_site 전체(arms.py:351–355): gamma 추정, Cx=A diag(gamma) A^H+eps I 구성, Hermitian 대칭화 및 Gaussian site 역행렬을 포함한다. 질의 (G,b) 구성·detector·BCJR는 H 밖이고 전체 rx.run 안에 포함된다.
- SBL 단계 수는 bench_cost.py:266–275에서 gamma 실행 범위에만 np.linalg.inv를 감싼다. arms.py:337–345의 반복당 역행렬(:339) 1회를 센다. 최종 site 역행렬(:354)은 H 시간에 포함하지만 EM 카운터에는 제외한다.
- 동결 SBL은 rho=4, n_em=3, cold이며 실제 update 기본값은 mackay(arms.py:296). 따라서 표의 EM=48은 여기서는 16×3 MacKay gamma 갱신 단계다. 엄밀한 EM 갱신식 48회라는 뜻은 아니다.
- 전체 시간은 bench_cost.py:375–384의 rx.run 호출만 perf_counter로 잰다. 모델/fit 로딩과 채널·송신·잡음 생성은 앞 단계에 있어 제외된다. Tap 설정/해제는 전체 시간 밖이며, 호출 중 wrapper·카운터 오버헤드는 시간 안에 있다(빼지 않음).
- 예외 블록은 시간 배열을 버리고 예외를 남긴다. early/nonfinite는 raw에 보존하고 요약에서 제외한다(:388–395,431). 이번 14행은 각각 개발 n=1, 예외/early/nonfinite=0.

5. 과제·원래 명세와 차이

- 과제는 기존 bench_moduleH_ep.py의 일반화를 적었고 상세 명세는 새 bench_cost.py 생성을 지시했다. 새 파일에 구현했고 역사적 bench는 유지했다.
- forward=16 기대와 실제 backbone=32가 다르다. 현재 정의의 기대 불일치를 그대로 출력하며, 값을 16으로 재명명하거나 기대값을 32로 바꿔 통과시킨 것은 아니다.
- 과제는 신경망 real64·수신기/GMM complex128을 요구하고 상세 명세는 실제 dtype을 읽으라고 했다. 확인된 network/복소 경로는 요구와 일치한다. 실수 행렬·고윳값까지 complex128이라고 과장하지 않는다.
- 상세 명세의 threadpoolctl torch-env 설치 대신, 이전 구현은 worktree 밖 쓰기 금지에 맞춰 cost/deps에 설치·fallback import했다. 경로·버전·SHA가 출력에 남아 있다. torch env 자체 설치와는 다르다.
- 실제 E4는 조용한 환경의 SNR별 24블록 조건이다. 기존 것은 --trials 1 --force 및 Tap/plain 확인이며 보고용 비용 측정이 아니다. 기존 CPU 66-67은 원래 확인 명세이고 이번 확인은 새 사용자 지시대로 1,97이다.
- --check-assets-only·--verify-tap·자산 경로 override는 거부/보존 확인을 위한 추가 인자다. 대체 경로도 고정 SHA를 만족해야 한다. --out-dir는 worktree의 cost 아래로 제한한다.
- D2 전체 fits에서 명세의 기준 SHA와 직접 대조하는 것은 실제 사용하는 fullK32와 kronK1024다. 나머지 파일은 읽은 SHA와 사본 SHA를 기록·대조하며 별도 사전 고정 SHA가 없다. 선택 객체가 kron K1024인지 추가 확인한다. U32는 각 태그에서 두 파일 모두 고정 SHA 대조.

첫 보강 확인은 verify_labels.sh의 set -e가 '잠기지 않음'을 뜻하는 lock id의 exit 1을 실패로 처리하여 Python 시작 전에 종료했다. labels_20261019_084909_CDT.{log,err}를 보존했다. 잠금 상태 조회가 검증을 중단하지 않게 래퍼를 고친 뒤 새 r2 로그로 완료했다. bench 결함이나 수신기 실행 실패는 아니다.
기존 guard·측정 확인 출력은 구현 확인 근거로 유효하다. 표기만 바뀌어 기존 수치의 재평가는 필요하지 않다. 조용한 조건의 실제 비용 결과로 사용하는 것은 부적절하다.
이번 작업은 저장 수치 재계산·배열 재비교이며, checkpoint 재평가·학습부터 재실행 또는 비용 측정의 재현이라고 부르지 않는다.

7. 남은 불확실성과 관측 범위

확인한 사실: 기존 개발 trial 2561, D2 2 SNR×3 arm 및 U32 2 SNR×4 arm에서 계측·결과 보존·스레드·K가 기록대로다. 독립 golden 보고와 관련 코드·거부 로그를 읽었으며, 이번에는 golden 수신기를 재실행하지 않았다. 공유 코드/기존 출력 보존은 SHA와 git diff로 확인했다.
미실행/미검증: 10/22–23 사용자 조건의 24블록 실제 측정, 조용한 환경에서의 비용 분포, 계측 오버헤드 크기, 새 torch 버전의 private VJP API 호환성. 현재 cost benchmark 자체는 lock id 기준 잠기지 않은 경로다.
개발 블록 수 1에서 만든 IQR은 rx.run에 대해 퇴화하므로 정식 비용 분포·서비스 지연·deadline/Pareto 결론을 내리지 않는다. GPU 더미 점유도 부하 가드의 다른 작업으로 잡히므로 실제 측정 조건은 별도로 충족해야 한다.
명세의 forward 16이 'denoise/네트워크+Jacobian 평가 한 번'을 의도했을 가능성은 해석일 뿐이다. 실행으로 확인된 것은 backbone 32와 논리적 VJP 1024/4096이며, 이 값들을 과제 기대와 구분해 보고한다.
