# SBL (MacKay) 채널 prior, cold/warm 정답 사례

구현 코드는 보지 않았다. 위임 메시지에 적힌 명세만으로 만들었다.

## 파일
- `golden_sbl_warm.json`: 사례 9개(C1–C5, B1–B4). B4는 선택 사례다. 호출마다 기대값 `gamma_start`, `gamma_end`, `gamma_end_exact`(정확한 분수 문자열), `Lambda`, `eta`가 들어 있다. 복소 배열은 `{re, im}` 중첩 리스트로 넣었다.
- `sbl_golden_ref.py`: 참조 구현과 비교 harness.
  - `SBLRef`: 명세를 그대로 옮긴 numpy complex128 구현이다.
  - `exact_run`: 가우스 유리수(`fractions.Fraction`)로 계산하는 독립 경로다. 바닥 1e-12와 ε = 1e-6도 정확한 유리수로 다룬다. JSON의 기대값은 이 경로의 결과를 float64로 반올림한 것이다.
  - `check_impl(make_obj, set_trial, get_gamma=None, include_optional=True)`: 실패 문자열 목록을 돌려준다. 빈 목록이면 통과다.
    - `make_obj(A, cbar, N, n_em, warm)`: `ep_site(G, b) -> (Lambda, eta)`를 가진 객체를 돌려줘야 한다.
    - `set_trial(t)`: 전역 '현재 시행 번호'를 t로 설정한다.
    - `get_gamma(obj)`: 마지막 호출이 끝난 뒤의 γ를 돌려준다(길이 M). 선택 인자다.
    - 구현의 클래스·인자·전역 변수 이름은 모르므로 이 셋은 harness를 쓰는 쪽이 연결한다.
- 실행: `taskset -c 0 ~/miniforge3/envs/torch/bin/python sbl_golden_ref.py`로 자기 점검을 한다. `--write`를 붙이면 JSON을 exact 경로로 다시 만든다.

## 비교 허용오차
| 항목 | 기준 |
|---|---|
| γ (`gamma_end`) | 원소별로 \|got − exp\| ≤ 1e-9 · exp. 기대 γ는 모두 1e-12 이상이고 양수다. |
| Λ | ‖got − exp‖_F ≤ 1e-9 · ‖exp‖_F |
| Λ Hermitian | ‖Λ − Λ^H‖_F ≤ 1e-15 · ‖Λ‖_F. 명세가 마지막에 (Λ+Λ^H)/2를 하므로 사실상 정확히 Hermitian이어야 한다. |
| η | 길이 N이고 모든 값이 정확히 0 |

허용오차가 넉넉한지는 명세와 대수적으로 같지만 계산 방식이 다른 두 변형으로 확인했다(명령은 아래 "검증 기록").
- `solve`(inv 대신 linalg.solve 사용): 모든 사례에서 오차가 1e-14 이하였다.
- 사후 공분산형(d를 1 − Σ_ii/γ_i로 계산해 소거 오차가 생기는 형태): 최대 오차가 C5의 γ_2 ≈ 1.85e-12에서 1.2e-10이었다. 나머지 사례는 4e-15 이하였다.

C5에서만 γ가 1e-9 근처의 오차로 실패하고 다른 항목이 모두 통과하면, 로직 결함보다 수치 형태 차이일 가능성이 높다. 반대로 아래 변이들은 O(1) 크기로 틀린다.

## 공통 설정
- S2: N = 2, M = 3이다(M > N).
  - A = [[1, 0, 1], [0, 1, j]]이고 a_3 = (1, j)다. cbar = 1.5이므로 평탄 초기값은 γ_0 = 1.5·2/3 = 1이다.
  - 이때 C0 = A A^H = [[2, −j], [j, 2]]다.
- G1 = diag(1, 2), b1 = (1, 0).
  - G1은 C0와 교환되지 않는다. 그래서 (I+GC)⁻¹와 (I+CG)⁻¹가 서로 다르다.
- G2 = [[1, j], [−j, 2]], b2 = (j, 1).
  - G2는 복소 Hermitian PD(det = 1)이고 b2도 복소수다. 그래서 G와 Gᵀ를 바꿔 쓰는 오류가 드러난다.
- S1: N = 1, M = 2, A = [[1, j]], cbar = 1이므로 γ_0 = 1/2다.

1. γ = (1,1,1)에서 C = C0이고, G1·C = [[2, −j], [2j, 4]]다.
2. I + G1C = [[3, −j], [2j, 5]]이고, det = 15 − (−j)(2j) = 13이다. 따라서 K = (1/13)[[5, j], [−2j, 3]]이다.
3. K b1 = (5, −2j)/13이고, A^H = [[1,0],[0,1],[1,−j]]다.
4. μ = (5/13, −2j/13, 5/13 + (−j)(−2j)/13) = (5/13, −2j/13, 3/13)이다.
5. K G1 = (1/13)[[5, 2j], [−2j, 6]]이므로 d = (5/13, 6/13, d_3)이다.

  1. C = [[44/91, −9j/91], [9j/91, 41/273]]이고, I + G1C = [[135/91, −9j/91], [18j/91, 355/273]]이다.

### B1 경계: b = 0 → 분자 바닥, warm에서는 바닥이 흡수 상태가 됨
- 호출 1(시행 1, (G1, 0)): μ = 0이므로 모든 γ_i = max(0, 1e-12) = **1e-12**다.
  - C_x = [[a, −δj], [δj, a]]이고 a = 1e-6 + 2e-12, δ = 1e-12다.
  - Λ = [[a, δj], [−δj, a]]/(a² − δ²) = [[999998.000005, 0.9999960000129999j], [−0.9999960000129999j, 999998.000005]].
- 호출 2(같은 시행, (G1, b1)): 1e-12에서 출발한다. 바닥 직전 값은 다음과 같다.
  - γ_1 = 1e-12·\|(K b1)_1\|² = 9.99999999996e-13 (분모는 바닥 1e-12).
  - γ_2 ≈ 2e-36, γ_3 ≈ 3.33e-13.
  - 따라서 모두 **1e-12**로 남고 Λ는 호출 1과 같다.
  - γ_1은 바닥과의 상대 차이가 4e-12라서 거의 동률이다. 하지만 어느 쪽으로 판정돼도 결과 차이가 4e-12라 허용오차 안이다.
- 호출 3(시행 2): 시행이 바뀌어 평탄 출발로 회복하고 C1과 같다.
- 객체 R(cold, b = 0)도 바닥 값과 호출 1의 Λ를 낸다.
- 동작상 시사점: warm에서 한 번 b = 0인 호출이 있으면, 같은 시행 안의 이후 호출은 γ가 바닥에 갇혀 Λ ≈ 1e6·I가 된다. 명세대로라면 이것이 정답이다.

### B2 경계: G = 0 → 분모 바닥(퇴화 입력, 명세 그대로)
- cold n_em = 1, (0, b1)이다.
- K = I, μ = Γ A^H b1 = (1, 0, 1), d = 0이므로 분모는 max(0, 1e-12) = 1e-12다.
- γ = (1/1e-12, 0 → 1e-12, 1/1e-12) = (**1e12, 1e-12, 1e12**).
- C_x ≈ [[2e12, −1e12 j], [1e12 j, 1e12]]이고 det ≈ 1e24이다.
- Λ = [[1e-12, 1e-12 j], [−1e-12 j, 2e-12]].
- 분모 바닥을 확인하는 사례는 이것 하나뿐이다. 바닥이 없으면 0/0 = nan이 된다.

### B3 경계: N = 1, M = 2, 두 warm 객체를 섞어 호출하고 cold의 상태 무시를 확인
손계산 공식: |a_i| = 1이고 g, b가 스칼라이면 γ_new,i = γ_i K |b|²/g, K = 1/(1 + g Σγ), Λ = 1/(Σγ + ε)다.

| # | 객체 | 시행 | b | 시작 γ | 끝 γ | Λ |
|---|---|---|---|---|---|---|
| 1 | P(warm) | 5 | 1 | 1/2 (첫 호출) | 1/4 | 1/(1/2+ε) = 1.999996000008 |
| 2 | Q(warm) | 5 | 2 | 1/2 (Q의 첫 호출, P와 공유 안 함) | 1 | 1/(2+ε) = 0.499999750000125 |
| 3 | P | 5 | 1 | 1/4 (P 자신의 직전 값) | 1/6 | 1/(1/3+ε) = 2.999991000027 |
| 4 | Q | 6 | 2 | 1/2 (시행 변경) | 1 | 0.499999750000125 |
| 5 | P | 6 | 1 | 1/2 (P의 직전 호출은 시행 5) | 1/4 | 1.999996000008 |
| 6 | P | 6 | 1 | 1/4 | 1/6 | 2.999991000027 |
| 7, 8 | R(cold) | 6 | 1 | 1/2 | 1/4 (두 번 다) | 1.999996000008 |

- 상태를 공유하는 구현이라면 3번은 Q의 끝값 1에서 출발해 1/3이 된다. 2번은 P의 끝값 1/4에서 출발해 1/4·(2/3)·4 = 2/3이 된다.
- 5번은 "다른 객체가 이미 시행 6을 봤다"는 이유로 warm이 되면 안 된다.

### B4 경계(선택): n_em = 0
- 명세에 n_em ≥ 1이라는 조건이 없어서 넣었다. 구현이 n_em = 0을 거부하면 `include_optional=False`로 뺀다.
- γ는 시작값 그대로다(1,1,1).
- Λ = inv(C0 + εI) = [[2+ε, j], [−j, 2+ε]]/((2+ε)² − 1) ≈ [[2/3, j/3], [−j/3, 2/3]]이다.
- warm 객체의 둘째 호출과 cold 객체도 같은 값을 낸다.

## 변이 검출(사례의 판별력)
`sbl_golden_ref.py`의 자기 점검 결과다. 모든 변이가 1개 이상의 사례에서 실패했다.

| 변이 | 내용 | 검출 사례 |
|---|---|---|
| CG | K = (I + C G)⁻¹ | C1–C5, B1 |
| KH | μ에 K^H b 사용 | C1–C5, B1 |
| AT | A^H 대신 Aᵀ 사용 | C1–C5, B1 |
| Gconj | G 대신 Gᵀ(= conj G) 사용 | C3, C4 |
| mu2 | \|μ\|² 대신 Re(μ²) 사용 | C1–C5, B1, B3 |
| noden | 분모 바닥 없음 | B2 |
| noreset | warm이 시행이 바뀌어도 재설정하지 않음 | C3, B1, B3 |
| shared | warm 상태를 객체끼리 공유 | B3 (C2, C3은 사례 간 누출로 부수적으로 검출) |
| warmflat | warm이 cold처럼 동작 | C2, C4, C5, B1, B3 |

## 명세에서 정해지지 않아 사례로 만들지 않은 것
- 시행 번호를 한 번도 설정하지 않은 상태(None 등)에서의 첫 호출. 첫 호출은 어쨌든 평탄 출발이다. 하지만 두 번째 호출에서 None == None을 같은 시행으로 볼지는 명세에 없다.
- cold 모드가 내부 상태를 기록하는지. cold는 상태를 읽지 않으므로 출력에는 영향이 없다.
- η의 dtype. 사례는 길이 N이고 값이 정확히 0인지만 본다.
