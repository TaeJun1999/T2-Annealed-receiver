# 10 — SPEC Stage C: 학습 prior의 예산-교정 재시도 (PRE-REGISTRATION)

작성 시각: 2026-09-21 13:59 KST
작성 시점 상태: **Stage C 결과를 하나도 보지 않은 상태.** D2 N=1.6e5 학습은 진행 중이며

## §0. 이 문서가 존재하는 이유, 그리고 무결성 앵커

Stage A5 의 사다리는 **N_train = 1e4** 에서 전부 게이트에 실패했고, 그 판정에 따라
`M-ours-dscore` 는 D1/D2 본 표에서 BLOCKED 이다. 그 판정은 **동결이며 이 문서로 바뀌지 않는다.**

그러나 Stage A5 이후 보고 전용으로 측정한 샘플복잡도(results/samplecx_D1.txt, samplecx.csv)는
실패의 성격을 구체적으로 특정한다. 등록 예산 1e4 에서 학습된 score 는

  GA 1.09e-15 (≤1e-6) PASS · GB 0.0117 (≤0.05) PASS · GD 0.1608 (≤0.20) PASS
  GC 0.2433 (≤0.15) **FAIL, 초과 배율 1.62**

즉 **네 게이트 중 셋을 이미 통과**했고 놓친 것은 score 자체의 상대오차 GC 하나뿐이다.
그리고 GC 는 측정된 스케일링 GC ~ N^(-0.474) (R^2 = 0.934) 를 따르며, 임계 0.15 통과가
N = 4e4 (0.1665 FAIL) 와 N = 1.6e5 (0.0999 PASS) 사이에서 **외삽이 아니라 실측으로** 괄호된다.
N = 1.6e5 에서는 네 게이트가 전부 통과한다 (gate_score 0.6657).

따라서 등록된 부정 결과의 정확한 내용은 **"학습 prior 는 이 수신기에 맞지 않는다"가 아니라
"등록 예산 1e4 에서는 score 정확도가 부족하다"** 이다. Stage C 는 그 한 문장을 검정한다.

### 무결성 앵커 (위반 시 Stage C 전체 폐기)

- A0. **Stage A/B 의 모든 판정은 동결.** `results/tables_D1.txt`, `results/tables_D2.txt`,
  `results/gate_D1.txt`, `LADDER.md` 는 수정·덮어쓰기 금지. Stage C 산출물은 전부 새 파일
  (`*_C.txt`, `raw_C/`, `LADDER_C.md`) 로 간다. 두 표는 **합치지 않는다.**
- A1. **게이트 임계값 불변**: GA 1e-6, GB 0.05, GC 0.15, GD 0.20. GD 는 계속 full Wirtinger
  행렬 상대 Frobenius 오차이며 `GD_trace` 는 보고 전용이다. 어떤 이유로도 완화하지 않는다.
- A2. **설계 근거는 BLER 이 아니다.** Stage C 의 모든 변경은 (i) 사전 측정된 샘플복잡도,
  (ii) §2 의 진단이 특정한 메커니즘, (iii) 수학적으로 강제되는 성질 — 이 셋 중 하나에서만
  나온다. BLER 을 보고 설계로 되돌아가는 것은 01_RULES §5 위반이며 금지다.
- A3. **동일 예산 유지.** 학습 prior 의 예산을 N' 로 올리면 GMM 도 같은 N' 로 재적합한다.
  같은 split, 같은 선택 규칙(검증 log-likelihood), 같은 후보 격자. 학습 prior 에만 데이터를
  더 주는 비교는 하지 않는다.
- A4. **레시피 재탐색 금지.** 아키텍처/하이퍼파라미터는 이미 끝난 HPO 의 D1 최적 구성을
  **그대로 복사**한다. 예산별 재탐색을 하지 않는다 (이것이 예산 효과와 탐색 효과를 분리한다).
- A5. **한 번만 실행.** §6 의 BLER 은 게이트 통과 시 1회만 돈다. 결과를 보고 재실행하지 않는다.
- A6. 실패 시에도 전부 보고한다. Stage C 가 실패하면 §7 의 형식으로 실패를 쓴다.

## §1. 검정할 가설

**H_C**: 학습된 score prior 가 사전 등록 게이트를 통과하지 못한 원인은 훈련 표본 수이며,
표본 수를 GC 가 임계를 넘는 수준(실측 괄호 N ∈ (4e4, 1.6e5])까지 올리고 **동일 예산을 GMM 에도
부여하면**, 학습 prior 는 게이트를 통과하고 수신기 안에서 발산하지 않는다.

보조 가설 **H_C2**: N=1e4 모델의 BLER 붕괴(results/tables_D2_supp.txt, NMSE > 1)는 단순한
부정확이 아니라 EP site 의 유효성 붕괴이며, 그것은 GD 가 측정하는 양이다. GD 가 0.161 → 0.072
로 개선되면 붕괴가 사라진다.

H_C 와 H_C2 는 서로 독립적으로 틀릴 수 있다. 둘 다 결과를 그대로 보고한다.

## §2. C1 — 붕괴 메커니즘 진단 (선행 조건)

N=1e4 모델의 발산 원인을 다섯 가설로 독립 측정한다 (실행 중, 산출물 `results/diag/`):
H1 야코비안이 대칭 PSD 가 아님 → D-14 site 분산 무효 · H2 σ 궤적이 학습 범위 이탈 ·
H3 정규화/스케일 불일치 · H4 배선(GMM 디노이저를 score 경로에 투입하는 교차실험) ·
H5 체크포인트 출처.

**분기 규칙 (사전 확정)**

- C1-a. 진단이 **인터페이스 결함**(H3/H4/H5 중 어느 것이든 CAUSAL)을 특정하면, 그것은 버그다.
  고치고, 수정은 **모든 score arm 에 동일 적용**하며, M1–M4 와 T-tests 로 재검증한다.
  GMM arm 코드 경로는 건드리지 않는다. 수정 전후 해시를 기록한다.
- C1-b. 진단이 **H1(야코비안 무효)**을 특정하면, §3 의 (F1) 을 적용한다.
- C1-c. 진단이 **H2(σ 범위 이탈)**를 특정하면, §3 의 (F2) 를 적용한다.
- C1-d. 진단이 어떤 것도 특정하지 못하면(전부 REFUTED/INCONCLUSIVE), 예산만 올린 채로
  §4 로 진행하고, 붕괴 원인 미해결을 §7 에 명시한다.

## §3. 적용할 수정 — 각각 사전 정당화 (BLER 무관)

셋 다 "성능이 안 나와서" 가 아니라 **참 posterior 가 만족해야 하는 성질** 또는 **이미 측정된 사실**
에서 나온다. 적용 여부는 §2 의 진단 결과가 결정하며, 적용하면 그 사실을 표에 명시한다.

- **(F1) D-14 site 의 대칭 PSD 투영.**
  근거: 가우시안 잡음 하 참 posterior-mean 디노이저는 J = Cov(h|q)/σ² 이므로 J 는 **반드시**
  대칭 PSD 이다. 신경망 야코비안은 이를 보장하지 않는다. 따라서
  J ← Π_PSD( (J + J^H)/2 ), 음의 고유값은 LAM_MIN=1e-6 으로 절단.
  이것은 튜닝 파라미터가 아니라 **알려진 제약 집합으로의 투영**이다. GMM arm 은 해석적으로
  이미 대칭 PSD 이므로 투영이 항등이며, 동일 코드를 통과시켜 그 사실을 시험으로 확인한다(신규 M6).
- **(F2) σ 범위 정렬.**
  근거: prior 를 학습 지지 밖에서 조회하면 그 출력은 정의되지 않는다. C1 의 계측이 기록한
  수신기 실제 조회 σ 범위를 학습 격자가 덮도록 확장한다. 덮는 범위만 바꾸고 격자 규칙(log-uniform)
  과 점 개수(20)는 유지한다.
- **(F3) Module H 발산 가드.**
  근거: R3(BiG-AMP)에는 이미 사전 등록된 `DIVERGE_NMSE = 10.0` 가드가 있는데 Module H 경로에는
  없다. **동일 상수 10.0 을 그대로 재사용**한다(새로 고르지 않는다). 가드 발동은 실패로 세고
  발동 횟수를 표에 보고한다. 가드는 모든 arm 의 Module H 경로에 동일 적용한다.

수정 (F1)–(F3) 중 실제로 적용한 것만 `LADDER_C.md` 머리말에 기록한다.

## §4. C2 — 예산과 레시피 (동결)

- 새 예산 **N' = 160,000** (학습 prior 와 GMM 모두). 근거: samplecx 에서 네 게이트를 통과한
  가장 작은 실측 점. 더 큰 값을 시도하지 않는다.
- split: 기존 규칙 그대로 (train:val = 9:1, `training_split` 의 해시를 기록).
- 레시피: HPO 의 D1 최적 구성을 **그대로**
  `dit / vp / angle, w64 d6 heads8 patch1, lr 2.238046051591068e-3, ema 0.999, batch 256, emb 256`.
  예산별 재탐색 금지 (A4).
- 시도 횟수: 최대 3 (사다리와 동일 규칙). early-stop 은 val loss patience 20, 최소 200 epoch,
  최대 3000. 그 조건을 못 채우면 `ABORTED` 이며 시도 슬롯을 쓰지 않는다.
- GMM: 동일 N' 로 `runner.py fit` 재실행. 후보 격자 K ∈ {16,32,64,128,256,512} × {full,kron},
  선택은 **검증 log-likelihood 단독**. BLER 은 선택에 절대 사용하지 않는다.

## §5. C3 — 게이트 (임계 불변)

- D1 에서 N' 로 학습한 체크포인트에 대해 GA/GB/GC/GD 를 보고용 held-out stream 10 에서 측정.
  `n_eval=512, n_jac=64`, 기존과 동일.
- **PASS 조건: GA ≤ 1e-6 AND GB ≤ 0.05 AND GC ≤ 0.15 AND GD ≤ 0.20.** 넷 다.
- 모든 시도를 `LADDER_C.md` 에 append. 실패를 삭제하지 않는다.
- D1 게이트가 통과해야만 D2 재학습본이 `M-ours-dscore-C` 로 자격을 얻는다.
  (게이트는 D1 에서만 측정 가능하다 — D2 에는 참 score 가 없다. 04_SPEC §5.)
- 보조로, GT 없는 진단 두 개를 D2 에서 함께 보고한다: GB′(디노이징) 와 Hyvarinen(score).
  **이 둘은 게이트가 아니다.** 판정은 오직 D1 게이트가 내린다.

## §5b. 게이트가 실패하면

Stage C 는 거기서 끝난다. BLER 을 돌리지 않는다. §7 형식으로 실패를 보고하고,
"N=1.6e5 에서 D1 은 통과했으나 D2 재학습본이 실패" 같은 구체적 내용을 남긴다.

## §6. C4 — BLER (게이트 통과 시 1회)

- 셀: **C2 (8×4, T=16, Tp=4)** 가 주 셀. 근거: 구조화 prior 의 효과가 나타난 셀이며 본 실험의
  headline 셀이다. 추가로 C1 (Tp=2) 와 C5 (Tp=3) 을 돌려 Tp 의존성을 함께 본다.
  (이 셀 선택은 BLER 을 보기 전에 여기 고정된다.)
- arm: `R2-ours-G`, `M-ours-bstar-C`(N' GMM), `M-ours-dscore-C`(N' score), `R1-turbo`, `R5-genie`.
- 판정점: 각 셀에서 기존 규칙과 동일하게 사전 결정된 3 SNR 점. 앵커 arm 은 `R2-ours-G`.
- 1차 비교 (사전 선언):
  1. `R2-ours-G → M-ours-dscore-C` — 학습 prior 가 가우시안 prior 대비 이득을 주는가
  2. `M-ours-bstar-C → M-ours-dscore-C` — 동일 예산에서 학습 prior 가 GMM 을 이기는가
  3. `M-ours-bstar-C` vs `M-ours-bstar` — GMM 이 예산 증가로 얼마나 좋아지는가 (공정성 확인)
- n: 판정점 n ≥ 2560, 그 외 n ≥ 640. n 을 640 미만으로 내리지 않는다.
- 유의성: 기존과 동일한 양측 부호검정 + 3점 규칙. 사후에 검정을 바꾸지 않는다.

## §8. Stage C 가 성공했을 때 정직하게 말할 수 있는 것 / 없는 것

**말할 수 있다**: 사전 등록된 게이트 하에서 학습 score prior 가 수신기 prior 로서 자격을 얻는 데
필요한 표본 수를 측정했고 (~5e4 에서 교차, 1.6e5 에서 통과), 그 예산에서 동일 예산의 GMM 대비
BLER 이 어떠한지.

**말할 수 없다**: 1e4 에서의 실패가 "튜닝 부족"이었다는 주장 (959 시도가 그 반대를 보인다).
D1 게이트 통과가 D2 성능을 보증한다는 주장 (게이트는 D1 에서만 측정된다 — 이 한계는 명시한다).
그리고 테스트베드 선택 근거는 **계속** "물리적으로 표준인 mmWave 희소 다중경로"이지
어느 방법에 유·불리해서가 아니다 (01_RULES §5).

아래 변형은 전부 그 목표에서 나오며, BLER 을 본 적이 없는 상태에서 여기 고정된다.

|---|---|---|---|
| **V0** (주 결과) | N'=1.6e5, 레시피 동결, 인터페이스 무변경 | 필요(진행 중) | H_C 를 순수하게 검정 |
| **V1** | V0 + (F1) site 의 대칭 PSD 투영 | 불필요 | 참 J 는 대칭 PSD — 알려진 제약집합으로의 투영 |
| **V2** | score 를 스칼라 에너지의 기울기로 매개화: s = -∇_x E_θ(x,σ) | 필요 | ∇s = -∇²E 는 **구성상 대칭**. 대칭성을 학습에 맡기지 않는다 |
| **V3** | V0 + 야코비안 정칙화 항 λ·E‖(J-Jᵀ)v‖² (Hutchinson) | 필요 | GD 가 재는 양을 손실에 직접 넣는다 |

## 다중성과 주·부 구분 (사전 확정)

- **주 결과는 V0 하나다.** 논문의 Stage C 1차 주장은 V0 에만 근거한다.
- V1~V3 은 **메커니즘 변형**이며 2차로 보고한다. 넷을 다 돌린 사실과 그 결과를 **전부** 보고한다.
  좋은 것만 고르지 않는다. 네 변형의 게이트·BLER 을 하나의 표에 나란히 싣는다.
- 변형 간 선택을 BLER 로 하지 않는다. arm 으로 승격할 변형은 **D1 게이트 통과 여부**로만 정한다.
  둘 이상이 통과하면 **둘 다** arm 으로 올리고 둘 다 보고한다.
- 게이트 임계는 여전히 불변 (GA 1e-6 / GB 0.05 / GC 0.15 / GD 0.20).
- V1 은 수신기 인터페이스 변경이므로 **모든 score arm 에 동일 적용**하고, GMM arm 에는
  적용 시 항등이어야 한다. 그 항등성을 신규 시험 **M6** 으로 검증하고, 실패하면 V1 을 폐기한다.
- V2/V3 은 A4(레시피 재탐색 금지)의 예외가 아니다. 두 변형 모두 **V0 과 동일한**
  arch/width/depth/lr/ema/batch/emb 를 쓰고, 바뀌는 것은 (V2) 출력 매개화, (V3) 손실 항뿐이다.
  V3 의 λ 는 탐색하지 않고 **단일 값 λ=1.0** 으로 고정한다 (튜닝하면 A2 위반).
- 계산 자원: V2/V3 학습은 유휴 GPU 에서 수행한다. GMM N'=1.6e5 적합(CPU)과 충돌하지 않는다.

## V2/V3 이 실패해도 보고한다

"구성상 대칭으로 만들어도 PSD 가 보장되지 않아 여전히 발산한다" 는 결과가 나오면 그것을 쓴다.
그 경우 결론은 **"EP 수신기에 확산 prior 를 쓰려면 디노이저의 2차 구조가 별도의 설계 대상이며,
표준 확산 지표(평균·score)로는 그것을 볼 수 없다"** 가 되고, 이는 그 자체로 결과다.

# §3c — V4: 스칼라 H site (증보, 출처 명시)

## 출처 (숨기지 않는다)

V1~V3 은 결과를 보기 전에 등록했다. **V4 는 그렇지 않다.** V4 는 §2 의 H4 진단 교차실험
(`results/diag/ep-site-integration_*`, n=128, 탐색적)에서 **관측된 뒤에** 등록된다. 그 사실을
여기 적고 논문에도 적는다. 정확한 경위:

- H4 의 목적은 "배선 탓인가 모델 탓인가"를 가르는 것이었고, 그 답은 **모델 탓**이었다:
  GMM 디노이저를 score 배선의 행렬 site 에 넣으면(`gmmB|scorew`) 정상 동작한다(NMSE 0.106/0.053/0.016).
  따라서 배선은 무죄이고 H1(야코비안 무효)이 원인이다.
- 그 실험은 부수적으로 `hsite=scalar` 조합도 측정했고, 거기서 학습 prior 가 살아났다.

## 사후 등록이지만 자의적이지 않은 이유 (사전 측정된 근거)

**GD_trace ≪ GD 는 2026-09-20 에 이미 측정되어 `LADDER.md` 에 82행 전부 기록돼 있다.**
전 사다리에 걸쳐 tr(J) 의 상대오차는 full 행렬 상대오차보다 한 자릿수 작았다
(예: L7a1 GD 0.1868 / GD_trace 0.0187 · L9a3 0.2405 / 0.0281 · N=1.6e5 0.0718 / 0.0075).
즉 **"학습 모델은 J 의 대각/트레이스는 잘 맞히지만 전체 행렬 구조는 못 맞힌다"** 는 사실은
V4 를 관측하기 훨씬 전부터 기록돼 있었고, 스칼라 site 는 그 사실의 직접적 귀결이다.

## 정의

- **V4** = score arm 의 Module H site 를 D-13 **믿음 스칼라화**만으로 구성하고 D-14 행렬 site 를
  쓰지 않는다 (`hsite=scalar, scal=belief`). 나머지(β=0.7, LOO, D-15 사후 피드백, 16 반복)는 동일.
- **V4b** = 동일하되 `scal=site`. 부수 보고용.
- 모델은 **게이트 통과 체크포인트만** 쓴다. 즉 N'=1.6e5 (GA/GB/GC/GD 전부 PASS, `LADDER_C.md`).
  게이트를 GD_trace 로 바꾸지 않는다 — V4 도 **네 게이트 전부**를 통과한 모델로만 만든다.
  (N=1.6e5 는 GD 0.0718 로 행렬 게이트도 통과하므로 특별 취급이 필요 없다.)

## 확증 실행 규칙 (여기서 고정, 결과 보기 전)

탐색적 n=128 결과는 **근거로 쓰지 않는다**. 별도의 확증 실행을 하고 그 결과만 주장한다.
- 셀 C2 (8×4 Tp=4) 주, C1·C5 부. 판정점 3개는 기존 규칙대로 사전 결정.
- n ≥ 2560 (판정점), n ≥ 640 (그 외). 1회만 실행, 결과를 보고 재실행하지 않는다.
- 1차 비교: `R2-ours-G → M-ours-dscore-C-V4`, `M-ours-bstar-C → M-ours-dscore-C-V4`.
- 양측 부호검정 + 3점 규칙, 사후 변경 없음.
- **대조군 필수**: 같은 실행에 `M-ours-bstar-C` 를 스칼라 site 로 돌린 arm 도 넣는다.
  스칼라화가 GMM 에도 이득이면 그것은 site 선택의 효과이지 학습 prior 의 효과가 아니다.
  탐색 단계에서 GMM 은 스칼라화로 좋아지지 않았지만(0.320 → 0.313/0.328), 확증에서 다시 확인한다.

## 보고 규칙

- 사전 등록 표의 `M-ours-dscore` (D-14 행렬 site, N=1e4) 판정은 **불변, BLOCKED 유지**.
- V4 는 별도 표에, "사후 등록 변형이며 H4 진단에서 관측된 뒤 등록됨" 을 명시해 싣는다.
- 행렬 site 의 실패와 스칼라 site 의 성공을 **같이** 보고한다. 이것이 결과의 핵심이다:
  학습 prior 의 1차 통계(평균·score)는 정확하고 2차 구조(야코비안)는 부정확하므로,
  **2차 구조를 요구하지 않는 site 를 쓰면 이득이 실현된다.**

# §3d — 학습 발산 폴백 (증보, 관측 경위 명시)

## 관측된 사실 (먼저 적는다)

동결 레시피(lr 2.238046e-3)로 V2·V3 를 학습했더니 **셋 다 수치적으로 발산**했다:

| 실행 | best val | 도달 epoch | 발산 후 val |
|---|---|---|---|
| V2 D2 N=1.6e5 | 3.653966e-01 | 85 | 5.92e+0 (ep 89) → 4.40e+0 (ep 113) |
| V2 D1 N=1.6e5 | 7.399451e-01 | 48 | 6.03e+3 (ep 52) |
| V3 D2 N=1.6e5 | 6.919234e-01 | 27 | 1.20e+0 (ep 60) |
| (참조) V0 a1 D2 | 3.595472e-01 | 661 | — 안정 |

**나는 폴백을 등록하기 전에 이 수치를 보았다.** 특히 V2 의 best val 3.654e-1 (85 ep) 가
V0 의 3.595e-1 (661 ep) 에 근접했다는 것도 보았다. 그 사실을 여기 적어 둔다.

## 선례와 정당화

01_RULES §4 / `code/bigamp.py` 는 **이미 같은 구조의 규칙을 갖고 있다**: R3-BiG-AMP 는 수치
발산 판정(`DIVERGE_NMSE = 10.0`)에 걸리면 사전 등록된 β 사다리 0.7 → 0.5 → 0.3 로 폴백하고,
시행마다 실제로 쓴 β 를 raw 에 기록한다. 그 규칙도 예비 실행에서 발산을 **관측한 뒤** 동결됐다.

여기서도 동일한 성질이 성립한다:
- 발동 조건이 **수치적**이다 — 게이트 값도, BLER 도 아니다.
- 폴백은 **최적화 안정화**이지 성능 튜닝이 아니다. 이중 역전파(∇를 통한 ∇)가 기울기 노름을
  키우는 것은 알려진 현상이고, 기울기 클리핑은 그에 대한 표준적·최소적 처방이다.
- 모든 시행을 `LADDER_C.md` 에 남기고 **발산한 시행을 지우지 않는다**.

## 규칙 (여기서 동결)

**발산 판정** `DIVERGE_TRAIN`: val loss 가 그때까지의 best 의 **3배**를 **연속 5 epoch** 초과하면
그 시행은 즉시 중단하고 **DIVERGED** 로 기록한다. DIVERGED 는 ABORTED 가 아니라 **완료된
시행**이며 시도 슬롯을 소비하고 결과로 보고된다. (min_epochs 200 규칙보다 우선한다 — 발산한
모델을 200 epoch 까지 끌고 가는 것은 자원 낭비이고 얻는 정보가 없다.)

**폴백 사다리** (발산 시 순서대로, 최대 3시행 규칙 안에서):
1. 시행 1 = 동결 레시피 그대로 (이미 실행됨, 전부 DIVERGED)
2. 시행 2 = 동결 레시피 + **전역 기울기 노름 클리핑 1.0**
3. 시행 3 = 동결 레시피 + 클리핑 1.0 + **lr/3**

숫자 1.0 과 3 은 여기서 고정하며 탐색하지 않는다. lr 자체는 재탐색하지 않는다(A4) — 사다리의
정해진 배율만 쓴다.

**적용 범위**: V2·V3 에만 적용하는 것이 아니라 **모든 Stage C 학습에 동일하게** 적용한다.
V0 은 발산하지 않았으므로 시행 1 이 그대로 유효하고 폴백이 발동하지 않는다. 만약 V0 이
나중에 발산하면 같은 사다리를 탄다.

**선택 규칙**: 폴백 시행 간 선택은 **검증 손실**로만 한다. 게이트 값으로도, BLER 로도 하지 않는다.
DIVERGED 시행의 best 체크포인트는 보존하되, 폴백이 성공하면 폴백본을 쓴다.

## 보고

`LADDER_C.md` 에 DIVERGED 시행과 폴백 시행이 모두 남는다. 표에는 "V2 는 동결 lr 에서
85 epoch 만에 val 3.654e-1 에 도달한 뒤 발산했고, 클리핑을 넣은 시행 2 의 결과는 …" 형식으로
**발산 사실과 함께** 보고한다. 발산을 숨기고 성공한 시행만 싣지 않는다.

# §6b — D1 확증 실행 (증보, 결과 관측 전)

## 왜 D1 도 도는가, 그리고 왜 이것이 우리에게 불리한 시험인가

§6 은 D2 만 지정했다. 여기에 **D1 을 추가**한다. 이유는 편의가 아니라 그 반대다:

**D1 은 참 prior 가 격자 GMM 으로 정의된 testbed 이므로 GMM arm 이 correctly specified 이고,
게다가 정확 score 의 oracle arm `M-ours-score` 까지 존재한다. 학습 prior 에게 가장 불리한 곳이다.**
01_RULES §1 의 "모호하면 우리 주장에 불리한 쪽" 규칙에 정확히 부합한다.

또한 실무적 이유가 있다: D1 의 게이트 통과 체크포인트 `ckpt/sx_N160000_D1.pt` 는 **이미 학습이
끝났고 게이트 PASS 가 기록돼 있다**(`gate_D1_C.txt`, `LADDER_C.md`). D2 체크포인트는 아직
학습 중이다. 끝난 것부터 돈다.

## 규칙 (결과를 보기 전에 고정)

- 체크포인트: `ckpt/sx_N160000_D1.pt` — GA 9.879e-16 / GB 2.659e-3 / GC 9.986e-2 / GD 7.183e-2, **PASS**.
- 셀: D1 의 기존 셀 집합. 판정점은 `tables_D1.txt` 에 이미 기록된 D1 의 사전 결정 판정점을 그대로 쓴다.
- arm: 기존 D1 arm 전부 + `M-ours-dscore-C-V0/V1/V4` + `M-ours-bstar-scalar`.
  **oracle `M-ours-score` 를 반드시 포함한다** — 정확 score 를 같은 인터페이스에 넣었을 때의 상한이며,
  학습 prior 가 그 상한에 얼마나 못 미치는지를 보여야 한다.
- n: 판정점 n ≥ 2560, 그 외 n ≥ 640. 640 미만으로 내리지 않는다.
- **예산 비대칭을 명시한다**: 학습 arm 은 N'=1.6e5, D1 의 GMM 적합은 기존 N=1e4 이다.
  이 실행에서 `R2-ours-G → M-ours-dscore-C-*` 는 읽되, **`M-ours-bstar → M-ours-dscore-C-*` 는
  동일예산이 아니므로 1차 비교로 쓰지 않는다** (A3). 표 헤더에 arm 별 N_train 을 싣는다.
  D1 의 동일예산 GMM 재적합은 하지 않는다 — D1 은 계측기이지 주장 testbed 가 아니므로
  거기에 CPU 를 쓰지 않고, 그 사실을 캐비엇으로 남긴다.
- 1차로 읽을 것: **V0(행렬 site) vs V1(PSD 투영) vs V4(스칼라 site)** — 같은 모델·같은 예산·
  같은 수신기에서 **site 구성만** 다른 3자 비교. 이것은 예산과 무관하게 공정하다.
- 1회만 실행한다. 결과를 보고 재실행하지 않는다.
- 출력은 `--tag C` 로 `raw_C/`, `tables_D1_C.txt`. 사전 등록 `tables_D1.txt` 는 불변.

## 예측 (기록해 두고 나중에 대조한다)

D2 진단에 근거해 다음을 예측한다. 빗나가면 빗나간 대로 보고한다.
1. `M-ours-dscore-C-V0` 는 게이트를 통과했음에도 D1 에서 **발산하거나 크게 나쁠 것**이다
   (야코비안 부정부호는 예산으로 해소되지 않으므로).
2. `M-ours-dscore-C-V1` 과 `-V4` 는 정상 동작할 것이다.
3. D1 에서는 GMM 이 correctly specified 이므로 **학습 prior 가 GMM 을 이기지 못할 가능성이 높다.**
   D2 에서와 반대 방향이 나와도 그것은 모순이 아니라 두 testbed 의 구조 차이다.
